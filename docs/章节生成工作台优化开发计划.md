# 章节生成工作台优化开发计划

## 目标

把章节生成页整理成完整的章节创作闭环：默认带入当前卷与目标章节大纲，按作者保存的大纲顺序生成下一章，保留可靠草稿；通过可配置的生成流程写作；支持使用项目记忆、章节上下文和会话历史进行整章或片段对话改稿；分析结果可审阅后沉淀到长期记忆；正文、版本、偏好和运行轨迹都能解释、恢复和追溯。

页面中可见的控件必须有真实行为。生成、改稿、分析、上下文、版本和轨迹之间共用一致的章节身份与正文版本，避免预览与实际执行不一致。

## 已确认的产品规则

1. 大纲/卷仍允许作者拖动排序。当前开发不锁定大纲顺序。
2. 新文章只生成当前大纲顺序中的下一章；作者选中旧章节时仍可编辑、改稿、分析和恢复版本，但不能把“生成新章”悄悄写回旧章节。
3. 章节序号跟随当前已保存的大纲顺序确定。大纲没有下一章时明确提示先补大纲；如果大纲顺序变化，章节身份仍以稳定的 `outline_id` 关联，不以列表位置或标题作为身份。
4. 章节生成提供快速写作、智能模式、深度创作。模式步骤、风格、节奏、目标和上下文都必须影响实际请求；已存在的三套后端流程优先复用并补齐真实参数传递。
5. 当前卷纲与目标章节大纲是生成必需上下文，默认加载且不可被普通上下文开关误关；项目记忆、人物/组织/世界观、伏笔、章节摘要等作为自动推荐或手动选择资料。必需、自动、手动三类要区分清楚；页面预览要对应后端实际读取结果。
6. 对话改稿按章节保存会话，默认范围为整章，也支持从正文选择连续片段。新建会话仍关联当前章节；调用可使用当前正文、章节会话历史与本次确认的项目记忆/上下文。候选稿先预览，作者明确应用后才修改正文并形成新版本。中断/失败不得丢弃已有正文、会话或候选结果。
7. 章节分析绑定被分析的正文版本；分析、摘要和资料变化先展示证据、来源与差异。分析提案可逐项审核、编辑、拒绝或确认沉淀到长期记忆；写入记录来源章节、正文版本和类别，并检查重复/冲突。涉及角色、世界观、组织、伏笔等设定的写回继续经过人工审核，不静默改设定。
8. 草稿自动保存与正式生成版本区分。刷新、重新进入章节后能恢复草稿；恢复旧版通过新增当前版本完成，不覆盖/删除版本历史；版本对比必须选两个版本。
9. 写作偏好按项目保存，编辑器字号按用户保存；临时调整只影响本次，不静默改默认偏好。
10. 轨迹按一次运行展示阶段、状态、耗时、实际 Token 用量/未提供用量、错误或中断原因，并关联上下文与版本；不直接向普通使用流程倾倒原始 JSON。
11. 对话优化的“思考过程”展示可理解的处理阶段、进度和简短处理摘要，不展示模型内部未整理的推理文本；用户可随时中断，界面明确区分已完成、正在处理、已中断和失败。
12. 上下文选择明确展示“必需带入、系统推荐、手动选择”三种来源，并说明每条资料是否实际进入本次请求；智能推荐只改变推荐项，不静默覆盖用户的手动选择。

## 当前检查结果

- 前端为 Vue 3 + TypeScript，章节生成页主要编排文件为 `frontend/src/pages/ChapterGeneratePage.vue`，已有编辑器、上下文、分析、对话和资源浏览组件，后续按职责继续拆分。
- 后端为 FastAPI + SQLAlchemy + SQLite，已有快速/智能/深度工作流、章节分析、变化提案、版本记录和运行步骤记录。
- 前端 `vue-tsc -b` 基线通过。
- 后端已有针对章节目标、生成控制、会话、分析新鲜度、版本历史等关键规则的自动化测试；本轮全量运行 25 项均通过。
- 标准 `npm run build` 在 Vite/esbuild 打包配置时遇到工作区上层目录访问拒绝；通过 Vite JS API 关闭重复配置打包、加载相同 Vue 插件和源码别名后，应用生产构建成功。产物有现存单包超过 500 KB 的体积提示。

## 开发阶段与提交节点

### 阶段 0：计划与基线（已完成）

- 固化规则、验收标准、范围和阶段依赖。
- 确认当前工作区状态、静态检查和构建阻塞点。
- 提交：`docs: 制定章节生成工作台优化计划`

### 阶段 1：章节身份与下一章规则（已完成）

- 检查卷/章大纲排序接口和草稿保存、生成持久化路径。
- 建立唯一的“下一章”解析规则，按已保存的大纲顺序和稳定 `outline_id` 关联正文。
- 生成入口固定指向下一章；明确区分“继续编辑当前章”和“生成下一章”；移除能让作者误把新稿写到任意章号的入口。
- 对空大纲、末章、旧章编辑、大纲重排、重复请求、空白草稿和已有正文补建章节等边界增加检查。
- 提交：`feat: 按大纲顺序生成下一章节`

### 阶段 2：生成控制、草稿与取消（已完成）

- 让快速/智能/深度三种工作流显示准确步骤说明，并核验每个生成参数确实进入后端提示和模型调用。
- 草稿自动保存、刷新恢复、切章未保存保护、生成中的中断/失败恢复互不覆盖。
- 提供真实取消能力；取消后留下可见运行状态和可恢复的已生成内容，防止迟到响应覆盖用户后续编辑。
- 统一生成错误反馈和重复提交保护。
- 提交：`feat: 完善章节生成控制与中断续跑`

### 阶段 3：章节对话改稿（已完成）

- 对话按项目/章节持久化，会话可新建、切换和恢复；默认整章，可选连续片段。
- 调用时使用当前正文、确认后的历史轮次和上下文快照；显示本次模型用量。
- 可取消进行中的对话；候选稿与原文并列预览，明确显示改动范围。
- 只有显式应用才写回，使用正文版本校验防止并发覆盖，并新增不可变版本。
- 提交：`feat: 持久化章节改稿会话并支持片段优化`

### 阶段 4：上下文和分析沉淀（已完成）

- 用真实的“本次生成上下文”解释必需、自动、手动资料及来源；自动推荐可修改，预览和运行使用同一快照。
- 分析结果标注正文版本和更新时间，正文变动后将旧分析/提案标为过期。
- 摘要、人物变化、关系、组织/世界设定、伏笔、时间线、连续性问题统一呈现来源证据和审阅状态。
- 仅在审核通过后写回；明确确认写回成功/失败。
- 提交：`feat: 统一章节上下文预览与分析审核`

### 阶段 5：版本、偏好与运行轨迹（已完成）

- 版本页去掉重复展示；提供可用的双版本比较、查看、收藏与安全恢复。恢复生成新版本，历史记录不可变。
- 版本区分自动草稿、生成稿和用户改稿，补足必要来源元数据。
- 按项目加载/保存写作偏好，用户级保存字号；区分默认设置和本章临时设置。
- 按运行聚合轨迹，正确显示步骤状态/耗时/Token、失败与取消，清理原始 JSON 与不实统计。
- 提交：`feat: 完善章节版本偏好与运行追踪`

### 阶段 6：结构整理与体验一致性

- 复用已有编辑器、上下文、分析、对话和资源浏览组件；将偏好、版本、轨迹面板拆成独立组件，页面保留章节生成主流程编排。
- 组件 props/events 和业务类型保持清晰，补充关键业务注释，不做无行为收益的纯搬迁。
- 收敛按钮文案、加载/空/错/取消状态、禁用条件、窄屏布局和键盘可达性。
- 提交：`refactor: 拆分章节生成工作台职责`（阶段提交）

### 阶段 7：回归验证和缺陷修复

- 执行关键业务规则检查、前端类型检查、前后端构建/编译。
- 启动真实本地前后端，用浏览器逐项验证：下一章、顺序重排、草稿恢复、三种生成模式、取消、对话历史/片段候选/应用、上下文快照、分析过期与审核、双版本比较/恢复、偏好作用域、轨迹和失败提示。
- 修复切章时旧章节版本恢复响应可能污染当前编辑器；按钮增加恢复中状态和防重复触发，并抑制切章后的旧错误提示。
- 独立提交：`fix: 隔离章节版本恢复的切章响应`；最终全量验证与 Git 状态核对完成。
- 补充隔离写入验证：版本恢复、过期快照冲突、偏好保存/读取和版本固化均通过临时数据库副本验证。最终复核时，浏览器自动化 CLI 无法获取所需组件，桌面浏览器也无法访问沙箱本机端口；因此本轮新增写路径以实际后端 API 验证及自动化回归为准，不宣称完成浏览器端写操作验收。
- 不推送远端、不执行生产发布；提交留在当前分支供作者审阅。

## 需求复核后的补充计划（2026-09-27）

本节是对早期阶段完成记录的验收补充，不否定已有提交，也不重复实现已验证通过的能力。早期阶段的“已完成”表示当时计划范围完成；以下项目须按本次复核后的更严格产品规则重新逐项审计。审计未通过的项目重新打开修复，不能仅凭旧阶段记录判定已满足。

### 已对齐的核心规则

- 当前卷纲和目标章节大纲默认且必需地进入章节生成；生成请求、上下文预览和运行轨迹都能看出其来源。
- “下一章”依据作者当前保存的大纲顺序计算。作者仍可拖动调整纲卷顺序；调整后按新顺序计算下一章。当前不锁定顺序，也不把缺章作为正常补章流程。
- 生成新章只能落在下一章；旧章节可以继续编辑、对话改稿、分析、比较和恢复版本。
- 对话改稿默认是当前章节会话，可新建会话；支持整章和正文连续片段优化，读取已确认的章节会话历史以及作者确认纳入的记忆/上下文。
- 分析提案先审阅，作者可将确认内容分类沉淀到长期记忆；任何分析结果都不得静默写入。
- 所有可见按钮必须有真实行为；正在运行的任务可以中断，状态和可恢复数据清楚可见。

### 补充阶段 A：规则与现状审计

- 逐项映射上述规则到页面控件、前端状态、API、数据库记录和自动化检查；形成规则—实现—验证矩阵。
- 特别核实：卷纲是否和章节大纲都进入真实模型请求；改稿是否实际使用所选记忆/历史；分析确认后是否真正写入长期记忆；中断是否阻止迟到结果覆盖正文。
- 将能力分为“已验证、仅有界面、仅有后端、缺失、行为不一致”，以实测结果确定后续工作，不以组件存在作为功能完成依据。
- 验收：每条核心规则至少有一个可复现验证路径、对应 API/组件位置和预期结果。

### 补充阶段 B：必需上下文和选择清晰度

- 将“当前卷纲、目标章节大纲”设为锁定的必需上下文；普通资料选择区不能将其移除。
- 资料选择区按必需、系统推荐、手动选择分组，展示已选数量、来源、纳入原因和本次是否实际读取；推荐操作保留用户手动选择。
- 生成前展示本次请求快照，至少列出大纲/卷、目标章节、正文草稿、已选记忆和其他资料；执行时使用同一快照并记录快照标识。
- 验收：关闭全部可选资料后仍包含卷纲与目标章纲；预览内容与后端实际请求一致；切换目标章后旧章纲不混入。

### 补充阶段 C：生成与章节改稿闭环

- 复核快速、智能、深度模式的选择反馈、适用场景、步骤说明和参数传递，突出“生成下一章”与“编辑当前章”的区别。
- 对话区提供章节会话列表、新建/切换/恢复；新会话默认绑定当前章节，已有会话不因切章或刷新丢失。
- 支持从编辑器选中连续文本直接发起片段优化，并把选中文本、必要邻近上下文、章节正文版本和会话历史一起纳入请求。
- 展示用户可理解的处理阶段、进度与简短处理摘要；保留中断入口。候选稿清楚标记替换范围，只有显式应用后才写入正文并生成新版本。
- 验收：整章和片段改稿均能使用作者确认的记忆/历史；中断、失败、切章和迟到响应不会破坏正文、历史会话或候选稿。

### 补充阶段 D：分析结果沉淀到长期记忆

- 分析结果逐项呈现类别、建议内容、证据摘录、来源章节、正文版本、潜在冲突和当前审核状态。
- 提供编辑后确认写入、拒绝、稍后处理等操作；确认前不改长期记忆。写入时选择长期记忆类别，并保存来源引用和去重/冲突处理结果。
- 正文版本变化后，旧分析及尚未确认的提案标为过期，禁止直接按旧结果写入；允许重新分析或由作者明确复核后继续。
- 验收：确认写入后能在长期记忆页查到并追溯来源；拒绝不产生写入；重复确认不会重复创建；冲突内容不会无提示覆盖已有记忆。

### 补充阶段 E：回归、可用性和提交

- 用真实运行验证大纲重排后的下一章、必需上下文、草稿恢复、三类生成模式、整章/片段改稿、记忆历史使用、中断、分析审核写入、版本恢复和运行 Token/阶段展示。
- 补齐窄屏与长内容状态下的选择可见性、滚动、键盘操作、加载/空/失败/中断提示；移除无效按钮或给出明确禁用原因。
- 每个补充阶段独立中文规范提交；提交前确认只包含该阶段文件和变更，最终记录自动化结果与手工验证边界。
- 最终验收：规则—实现—验证矩阵无未解释项；前端类型检查、生产构建、后端针对性回归和运行流程检查通过；环境无法验证的项明确列出，不宣称通过。

### 补充范围与设计边界

- 不展示模型原始隐式推理；“思考过程”仅为可解释的阶段状态和简短处理摘要。
- 记忆写回必须由作者逐项确认；不自动把整篇章节正文或所有分析结果灌入长期记忆。
- 不改变已确认的大纲可拖动排序和新章仅生成下一章规则；不扩大为全站改版。
- 本补充计划先审计后开发；已有功能只有在满足补充验收条件并有可复现证据时才沿用“已完成”状态。

## 验收标准

- 不能通过手填任意章节号绕开“新章只到下一章”规则；已保存的大纲拖动排序会影响下一章目标，但不会丢失现有章节关联。
- 刷新/切页不丢正文草稿、对话历史或尚未应用的候选；用户取消或失败也不丢可恢复数据。
- 生成、上下文预览、改稿、分析显示的章节和正文版本一致；后端返回的实际上下文能在页面看懂。
- 变化提案只有审核通过才改设定；拒绝提案不更改设定；旧正文分析不会冒充最新分析。
- 历史版本不会被覆盖；恢复操作会创建新的当前版本；版本对比始终对应所选两版。
- 每个可见按钮都能完成说明中的行为，或者明确处于不可用状态并解释原因。
- 每阶段都有可读的中文规范提交记录，最终验证结果明确区分通过、失败和环境受限。

## 范围控制

- 此计划聚焦章节生成工作台和其直接依赖的章节/大纲/工作流 API，不顺带重做其他系统页面。
- 目前不锁定大纲排序，也不改变既有章节正文和设定数据；数据库变更必须可向前兼容。
- 取消请求应安全终止模型调用或至少使服务端停止提交结果；若当前模型服务无法真正中断，必须清晰标注取消状态并隔离迟到响应，不能伪装为已停止。
- 每阶段先检查已有实现并复用，不为满足计划重复造功能。
