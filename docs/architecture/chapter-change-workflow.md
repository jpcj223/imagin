# 章节变化闭环实施计划

## 目标

让章节正文成为“发生了什么”的来源，让人物、关系、组织、伏笔和世界观资料成为“当前已确认状态”。Agent 负责分析并提出变化，应用服务负责校验、审核后的写回和来源留痕。

## 当前架构判断

- 前端是 Vue 3 + TypeScript，后端是 FastAPI，创作资料使用 SQLAlchemy 和业务数据库。
- 后端有旧版直接调用式 Agent 接口和 V3 模板工作流两条路径。
- V3 工作流会保存运行、步骤结果和会话上下文，记忆检索器会读取项目资料与近期章节摘要。
- 章节摘要已经保存人物/世界观变化、伏笔和时间线文本，但这些文本尚未形成可审核、可应用的变更记录。
- 人物关系目前嵌在 `characters.character_relations` JSON 字段中，不是独立关系表。

## 目标数据流

1. 读取本章大纲、项目资料、已确认记忆和前情摘要。
2. 规划、写作、精修；明确把最终正文传给分析步骤。
3. 分析器返回有类型的结构化结果，并解析人物、关系、组织、伏笔、世界观与时间线变化。
4. 校验项目内实体引用，把变化保存为待审核提案；保留章节、运行、版本、依据和变更前快照。
5. 作者逐条确认、修改或拒绝。确认时检查资料是否已被其他操作修改，再事务性写回。
6. 记录应用结果和来源，后续章节检索只读取已确认的当前状态。

## 分阶段实施

### 阶段一：变更提案基础（已完成）

- 新增业务表和 ORM 模型，保存提案、审核状态、来源、前值和拟议值。
- 新增带项目/章节范围校验的提案创建、查询、审核接口。
- 支持人物、人物关系、组织、伏笔、世界观和长期记忆的安全写回；使用字段白名单、项目归属校验、前值冲突检测和幂等键。
- 给后续分析接入提供稳定 API 契约，不让模型直接写当前资料。

### 阶段二：结构化章节分析（已完成）

- 定义 Pydantic 输出契约和分析提示词。
- 修正正文、精修正文与分析步骤之间的输入映射。
- 将分析结果映射为章节摘要及提案；生成流程仅创建提案，不自动应用高风险资料变化。

### 阶段三：前端审核与记忆浏览（已完成）

- 在章节工作台展示待审核变化，提供逐条确认、修改、拒绝和冲突提示。
- 审核后刷新人物、关系、组织、伏笔和记忆资料。
- 长期记忆中心可分别浏览章节摘要与已沉淀记忆条目，并查看条目内容和来源引用。

### 阶段四：后续章节上下文与收尾（进行中）

- 后续章节会读取正式人物、关系、组织、伏笔、世界观卡片，以及审核通过的长期记忆和近期章节摘要。
- 旧版手动章节分析与 V3 分析器已统一结构化契约和提案服务。
- 后续还需改进按大纲相关度检索长期记忆、展示实体变更历史，并补充分层错误恢复与回归验证。

## 代码约定

- 关键服务方法的注释按“步骤 1、步骤 2……”说明数据流。
- Agent 产物与持久化写回分层：模型输出只能创建候选，写回必须经过审核服务。
- 写回使用业务库单事务；遇到前值变化时标记冲突，不覆盖新状态。
- 所有提案均带稳定幂等键，重试分析请求不会重复写入同一个候选。
