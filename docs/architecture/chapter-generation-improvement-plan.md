# 章节生成核心链路分析与迭代计划

## 目标

让章节生成成为可靠、可解释、可恢复的创作闭环：以本章大纲和截止到本章的已确认资料为依据，先规划再写作；最终正文明确保存为版本；分析只读取最终保存正文，并生成可审核的摘要和设定变更候选；中断后可以从正确步骤继续，不重复正文，也不把模型兜底样例误存成真实分析。

## 当前链路

1. `ChapterGeneratePage.vue` 负责选择大纲、设置生成参数、展示上下文、正文编辑、工作流步骤、版本和变化提案。
2. V3 工作流模板包括快速写作、智能模式（规划→写作→分析）和深度创作（规划→写作→精修→分析）。旧版独立生成和分析接口仍保留。
3. `WorkflowEngine` 组装项目资料和会话状态，调用 Planner、Writer、Polisher、Analyzer；`agents_v3` API 保存最终正文、版本、章节摘要和待审核提案。
4. 提案经作者审核后才写回人物、关系、组织、伏笔、世界观和长期记忆；后续章节读取已确认资料。

## 代码检查发现

| 优先级 | 问题 | 影响 |
| --- | --- | --- |
| P0 | 恢复工作流时会原样恢复 `running` / `failed` 步骤状态，而调度器只执行 `pending`；传输中断或步骤失败后点“继续”可能不再执行任何步骤。 | 核心写作不可恢复；前端可能把非 completed 状态显示成续跑完成。 |
| P0 | DynamicAgent 将模型错误转换成示例兜底文本并照常完成；Analyzer 兜底文本会被解析成摘要并可能落库。 | 生成状态虚报成功，开发占位内容污染正式章节摘要。 |
| P1 | 智能模式执行 Planner 并保存 `writing_plan`，但 Writer Prompt 没有引用它。 | 页面显示三步流程，规划结果实际没有指导正文。 |
| P1 | `MemoryRetriever` 用用户补充要求作为人物和伏笔的整体 `LIKE` 条件；普通自然语言要求很难命中实体字段。 | 有明确要求时反而容易漏掉人物卡和伏笔。 |
| P1 | `MemoryRetriever` 与旧版 `build_chapter_context` 是两套上下文逻辑，人物/伏笔数量、相关组织、记忆排序可能不一致。 | 预览与不同生成入口可能看到不同资料，难以解释生成偏差。 |
| P1 | 长期记忆读取按最近更新排序，记忆条目没有章节截止过滤；在补写早期章节时，后续章节沉淀的记忆可能进入上下文。 | 可能造成时间线穿越和提前泄露剧情。 |
| P2 | 前端生成、续跑和步骤重跑重复维护事件处理；续跑与重跑的分析字段回填不完整，写作步骤重跑时可能把新流式正文接到旧正文后面。 | 不同操作后的页面状态、正文和分析显示不一致。 |
| P2 | 现有工作流步骤快照记录输入摘要，但缺少充分的有效输入/最终正文标识与完成状态反馈。 | 排查“模型实际看到了什么”以及“分析的是哪份正文”较困难。 |

## 目标规则

- 章节输入以所选大纲、用户要求、节奏、世界观、相关人物/组织/关系/伏笔、前情摘要和本章可见的已确认记忆组成。
- 时间边界以章节号为准：前情摘要必须早于本章；有章节来源的记忆不得来自本章之后；没有章节来源的项目级稳定设定可以继续读取。
- Planner 输出必须显式进入 Writer 输入。快速写作模板没有 Planner 时仍可直接写作。
- Analyzer 只分析最终正文：深度创作分析精修稿，其他模板分析写作稿；人工编辑后的分析以编辑器当前正文为准。
- 模型兜底稿必须带 `fallback` 来源状态；不得将兜底分析保存为正式摘要或创建变化提案。兜底正文可用于界面和流程调试，但必须明确标识。
- 工作流重试只重跑最后一个未完成步骤及其下游步骤；已完成上游步骤的输出保留。重跑 Writer 时界面清空旧的流式片段，避免拼接。
- 只有工作流明确 `completed` 且有非空最终正文，才保存正式草稿版本和变化提案；失败要明确显示，不可伪装完成。
- 人物/关系/组织/伏笔/世界观变更仍进入待审核提案，不由生成器直接覆盖设定。

## 分阶段实施

### 阶段一：工作流可靠性与规划衔接

- 修复恢复时 `running` / `failed` 步骤卡住的问题，并清除重试后的运行错误状态。
- 让续跑和步骤重跑清楚地区分 `completed`、`failed` 与仍有待执行步骤；非 completed 不得当作成功。
- 分析 Agent 使用 fallback 时标记分析不可用；保存正文版本，但跳过假摘要和假提案，并向前端展示状态。
- 将 `writing_plan` 纳入 Writer Prompt；保留快速写作模式不依赖 Planner 的行为。
- Writer 重跑或恢复时清理旧流式片段，精修稿仍使用最终稿语义。

验收要点：失败/断流步骤可以重试；已完成步骤不重复；Writer 能收到 Planner 结果；Analyzer fallback 不会进入摘要或提案；只有 completed 才呈现成功。

### 阶段二：统一、可解释的上下文装配

- 选择一套公共上下文服务供预览、旧版生成、V3 工作流与分析使用，避免两套 SQL 查询各自漂移。
- 将大纲标题、描述和用户要求作为统一检索线索；人物、组织、世界观和伏笔按名称、章节/实体关联、重要性及文本相关度排序，不用整段要求做精确子串过滤。
- 完整保留作者手选项、正文点名实体、主角及结构化关联的伏笔，再按相关度补充自动推荐资料。
- 按本章时间边界过滤前情和有章节来源的长期记忆；世界观设定按本章关联、文本相关度和重要性推荐。
- 在上下文预览区显示真实注入资料，并标识手动选择项和自动推荐项。

验收要点：上下文预览与实际 Agent 输入使用同一检索器；手选和结构化强关联资料不被默认条数截断；改变补充要求不再导致角色列表清空；生成早期章节不读取未来摘要/记忆；预览区区分手选与自动推荐。

### 阶段三：最终正文、版本与分析关联

- 已完成：明确每个模板选用精修稿或写作稿，保存正文前校验非空，并把工作流摘要绑定到来源运行和正文版本。
- 已完成：流式接口在正文、版本、摘要和提案落库后才发出成功事件；保存失败时前端收到错误，不会提前显示完成。
- 已完成：普通续跑发现运行已有版本时拒绝重复持久化；指定步骤重跑仍可产生新版本。
- 编辑器手动分析前后文和版本关联准确；编辑内容未保存为版本时不能错误挂到旧版本。
- 续跑和步骤重跑后刷新正文、版本、章节摘要、提案和工作台状态。
- 失败保留可恢复草稿，但不创建完成版本、不记成功摘要。

验收要点：每条摘要/提案都能追溯到章节、运行和版本；深度创作分析精修稿；编辑器人工分析输入与屏幕正文一致。

### 阶段四：体验与可观测性

- 合并前端重复的生成/续跑/重跑事件处理，统一分析回填、错误、进度和状态展示。
- 展示上下文概要、工作流状态、当前步骤、重试入口和模型兜底提示。
- 补齐步骤实际输入摘要、模型来源、耗时和 Token 统计的可读展示。
- 整理旧版入口：先确保与共享服务兼容，再逐步收敛到 V3，避免一次性破坏现有接口。

验收要点：生成、失败、续跑、步骤重跑和手动分析有一致状态；用户可判断本次生成使用的资料、正文版本和模型来源。

## 本轮执行顺序

1. 先提交本计划。
2. 立即完成阶段一中“恢复/重试、兜底分析隔离、Planner→Writer 衔接”功能块并独立提交。
3. 再完成阶段二中的上下文检索改进并独立提交，保证预览和真实输入不分叉。
4. 最后按当前代码风险推进阶段三，整理工作台对成功/失败和分析结果的反馈；每个可独立回顾的功能块单独提交。

## 实施记录

- 已完成：章节生成分析与分阶段计划，提交 `docs: 制定章节生成质量迭代计划`。
- 已完成：工作流恢复、兜底分析隔离、规划结果传入写作，提交 `fix: 修复章节工作流恢复和兜底分析`。
- 已完成：预览、旧版生成、V3 生成与续跑共用章节上下文检索；完整保留手选/强关联实体，按章节截止过滤记忆，并展示实际注入的上下文资料。
- 已完成：阶段三为章节摘要记录来源运行和正文版本，长期记忆详情显示来源；人工分析只关联正文与当前版本完全一致的摘要。
- 已完成：流式成功通知等待最终内容持久化；普通续跑避免对已完成运行重复创建版本。
- 进行中：阶段三剩余的工作台交互状态与编辑器手动分析体验。

## 变更与提交约定

- 核心方法和关键数据流使用中文步骤注释。
- 按独立功能块提交，遵循 Conventional Commits，例如 `docs:`、`fix:`、`feat:`。
- 每次提交前检查差异与空白错误；除非用户要求，不运行测试。
