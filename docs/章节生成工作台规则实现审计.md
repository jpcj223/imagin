# 章节生成工作台规则实现审计

审计日期：2026-09-27  
依据：用户确认的章节生成规则、`docs/章节生成工作台优化开发计划.md` 及当前前后端实现。

## 结论

下一章定位、章节改稿会话、候选稿确认、中断入口、分析提案审核和版本保护已有实现。审计发现两项与已确认需求不一致的上下文缺口：

1. 生成上下文包含目标章节大纲，但没有读取其所属卷纲。界面“每次生成必读”也只展示本章大纲和世界观。
2. 对话改稿调用统一检索器并拿到长期记忆，但 `_compact_context` 组装提示时丢弃了长期记忆；因此界面上下文选择中的记忆并未真正帮助对话改稿。

初次审计确认这两项会造成生成与改稿请求对故事背景理解不完整。阶段 B 已将卷纲补入生成、改稿和预览，阶段 C 已将确认的长期记忆补入改稿提示；两项均已通过对应回归。后续重点转为分析提案写回长期记忆的专项验证。

## 开发顺序

### 阶段 A：审计基线（已完成）

- 形成上述规则—实现—验证矩阵。
- 保留已有通过项，避免重复实现。
- 本次代码修复从阶段 B 开始。

### 阶段 B：卷纲进入必需上下文

状态：已完成。

- 由目标章节的 `volume_id` 解析所属项目卷节点，校验项目归属和节点类型。
- 在记忆包新增卷纲结构，包含卷号、标题、描述；没有卷纲或关联卷不存在时明确返回空值，不影响旧数据和无卷章节。
- 将卷纲注入生成提示、章节改稿提示和上下文预览；预览标为“每次生成必读”，不纳入可关闭的普通资料选择。
- 增加单元测试：有关联卷、无关联卷、无效卷 ID、不同项目同 ID 安全隔离，以及预览与提示词包含一致的卷纲内容。
- 完成前端类型检查、后端针对性测试和构建检查。
- 阶段提交：`feat: 将卷纲纳入章节生成上下文`。

### 阶段 C：改稿注入长期记忆

状态：已完成。

- 在 `_compact_context` 中压缩纳入长期记忆的标题、类别、摘要和来源信息；设置条数和长度上限，避免记忆淹没当前正文与用户指令。
- 保持已有检索器的章节时间边界，不能把当前章或未来章节来源的记忆泄漏到当前/旧章节改稿。
- 扩展改稿服务测试，断言模型请求包含检索到的记忆与最近章节摘要，并断言无记忆时仍可正常改稿。
- 阶段提交：`feat: 让章节改稿使用项目长期记忆`。

### 阶段 D：长期记忆提案专项验证

状态：已完成。

- 对审核确认、拒绝、重复确认和正文过期场景建立服务级测试。
- 验证批准的 `MemoryItem` 包含项目、类型、内容以及来源章节、来源版本、正文指纹和提案引用；长期记忆列表 API 可以按来源引用检索。
- 审核确认会将受控来源信息合并进记忆元数据；拒绝不会写入，重复批准返回幂等结果；`metadata_json` 必须为对象，避免审核时发生非预期服务错误。
- 过期正文与缺少来源指纹的旧提案仍被阻止批准；没有数据库迁移，旧记忆继续可读。
- 阶段提交：`feat: 补齐章节分析记忆来源追踪`。

## 范围和安全边界

- 本轮优先解决上下文真实输入缺口，不重写章节生成架构，不改动用户小说数据。
- 卷纲是必需背景但不改变“下一章”计算；当前大纲排序仍按作者保存顺序生效。
- 长期记忆只由作者批准的分析提案写入；章节摘要仍作为独立的章节前情摘要管理。
- 流程状态可以展示“读取卷纲/章节大纲/记忆、分析正文、生成候选”等进度，不展示模型内部未整理的推理文本。
